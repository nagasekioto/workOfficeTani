# パスワード・秘密情報の取り扱い方針

本システムで扱う「秘密の値」について、**どこに置くか・どう作るか・いつ変えるか**を定めたものです。

対象: 家政婦紹介事務所 人物管理システム
最終更新: 2026-07-29

---

## 1. 基本の考え方

### 1-1. 画面のログインに「パスワード」は使いません

本システムのログインは **Google Authenticator（TOTP）の6桁コード**だけです。
全員共通のパスワード方式は**廃止しました**（コードごと削除済み）。

理由は次のとおりです。

- 共通パスワードは、値を知った人が誰でも・どこからでも・何度でも入れる
- 退職した人が覚えていても、変更するまで有効なまま
- 「誰がログインしたか」が記録できない
- 漏れた時点で防御がゼロになる（「知っているもの」1要素しかないため）

ハッシュ化しても上記は解決しないため、**パスワードという仕組み自体を無くす**方針を採りました。

> 📌 設定を1つ変えれば旧方式に戻せる、という状態も作っていません。
> 迂回できる経路が残っていると、そこが抜け道になるためです。

### 1-2. 秘密の値は設定ファイルに書きません

DBパスワードなどの接続情報は、**環境変数からのみ**読み込みます。

設定ファイル（`application.yml`）に書くと、次の2つが同時に起きます。

1. GitHubのリポジトリに載る（閲覧できる人全員に知られる）
2. **コミット履歴に永久に残る**（後から消しても履歴からは消えない）

### 1-3. 既定値に本物の値を置きません

```yaml
# ❌ してはいけない書き方
password: ${DB_PASSWORD:7136}

# ✅ 正しい書き方
password: ${DB_PASSWORD}
```

既定値に本物を書くと、**環境変数を設定し忘れても動いてしまい、設定漏れに気付けません**。
未設定なら起動時にエラーになるのが正しい状態です。

## 2. 秘密の値の一覧

| # | 名称 | 何に使うか | どこに置くか | 未設定時の動作 |
|---|------|-----------|-------------|---------------|
| 1 | `DB_PASSWORD` | PostgreSQLへの接続 | システム環境変数 | **起動しない** |
| 2 | `TOTP_ENCRYPTION_KEY` | ログイン情報の暗号化 | システム環境変数 | 起動時に警告。ログイン・登録はできない |
| 3 | バックアップコード | 認証アプリ紛失時のログイン | **紙のみ**（DBにはハッシュのみ） | – |
| 4 | GitHubアクセストークン | ソースの取得・更新 | Windows資格情報マネージャー | `git pull` できない |
| 5 | Windowsサインインパスワード | パソコン本体 | 記憶（紙に書くなら鍵付き） | – |
| 6 | バックアップ用クラウドのパスワード | 遠隔バックアップ | パスワード管理ソフト | – |

**保管場所の記録は `SECURITY_CHECKLIST.md` 第3章に記入してください。**

## 3. 値の作り方（強度の要件）

| 対象 | 要件 |
|------|------|
| `DB_PASSWORD` | **20文字以上**。英大文字・小文字・数字・記号を混ぜる。他で使っていない値 |
| `TOTP_ENCRYPTION_KEY` | **30文字以上**。ランダム。人が覚える必要はないので長くしてよい |
| Windowsサインイン | **12文字以上**。他で使っていない値 |
| クラウドのパスワード | **12文字以上**＋そのサービスの二要素認証を有効にする |

### 作り方の例（PowerShell）

```powershell
# 32文字のランダムな文字列を作る
-join ((48..57) + (65..90) + (97..122) | Get-Random -Count 32 | ForEach-Object { [char]$_ })
```

> ⚠️ 作った値を画面に出したまま席を離れないでください。
> 使い終わったらPowerShellの履歴も消してください（`Clear-History` とウィンドウを閉じる）。

### 使ってはいけない値

- 事務所名・システム名・人名・生年月日・電話番号から作った値
- `7136` `tani` など、これまで使っていた値の再利用
- 他のサービスで使っている値の使い回し

## 4. 設定のしかた

管理者権限のPowerShellで実行します。

```powershell
[Environment]::SetEnvironmentVariable("DB_PASSWORD", "（実際の値）", "Machine")
[Environment]::SetEnvironmentVariable("TOTP_ENCRYPTION_KEY", "（実際の値）", "Machine")
```

設定後、**PowerShellを開き直してから**システムを起動してください。

`Machine`（システム環境変数）にしているのは、バックアップの自動実行が `SYSTEM` アカウントで
動くためです。ユーザー環境変数にすると自動バックアップから読めません。

**確認**

```powershell
[Environment]::GetEnvironmentVariable("DB_PASSWORD", "Machine")
```

## 5. 変更（ローテーション）

### 5-1. 変更する周期

| 対象 | 周期 | これに加えて変更するとき |
|------|------|----------------------|
| `DB_PASSWORD` | 1年 | 担当者の交代時、漏えいの疑いがあるとき |
| `TOTP_ENCRYPTION_KEY` | 原則変更しない | 漏えいの疑いがあるときのみ（→ 5-3） |
| バックアップコード | 使ったつど | 紙を紛失・盗難の疑いがあるとき |
| GitHubトークン | 1年（有効期限を設定する） | 漏えいの疑いがあるとき |

### 5-2. `DB_PASSWORD` を変える手順

**順番を守ってください。先に新しい値を控えてから変更します。**

1. バックアップを取る（`C:\workOfficeTani\backup\backup.ps1`）
2. システムを停止する
3. 新しい値を決め、**先に紙とパスワード管理ソフトへ記録する**
4. PostgreSQL側を変更する

```powershell
$env:PGPASSWORD = Read-Host "現在のパスワードを入力" -AsSecureString | ConvertFrom-SecureString -AsPlainText
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" -U postgres -h localhost -d postgres -c "ALTER ROLE postgres WITH PASSWORD '（新しい値）';"
```

5. 環境変数を新しい値に更新する（第4章）
6. PowerShellを開き直してシステムを起動する
7. **ログインして求職者一覧が表示されることを確認する**
8. `SECURITY_CHECKLIST.md` 第3章の最終更新日を書き換える

### 5-3. `TOTP_ENCRYPTION_KEY` を変える場合

**この値を変えると、全利用者のログイン情報が復号できなくなります。**
つまり全員が認証アプリでログインできなくなります。

実行する前に、必ず**印刷したバックアップコードが手元にあること**を確認してください。
手順は `INCIDENT_RESPONSE.md` の 3-2(c) を参照してください。

## 6. 【重要】いま残っている作業

### 6-1. `7136` と `tani` は、まだ有効な値です

設定ファイルからは削除しましたが、**次の2つは未対応です**。

1. **PostgreSQLの `postgres` ロールのパスワードは、いまも `7136` のまま**です
2. `7136` と `tani` は、**このリポジトリのコミット履歴に残っています**

コードから消しても履歴からは消えないため、
**リポジトリを閲覧できる人は、今も両方の値を知ることができます。**

### 6-2. やるべきこと

- ☐ 第3章の要件に沿って新しいDBパスワードを作る
- ☐ 5-2の手順で `postgres` ロールのパスワードを変更する
- ☐ 環境変数 `DB_PASSWORD` に新しい値を設定する
- ☐ `TOTP_ENCRYPTION_KEY` を設定する（未設定ならログインできません）
- ☐ GitHubのアクセストークンを失効させる（`SECURITY_CHECKLIST.md` 5-1）
- ☐ バックアップスクリプト `backup.ps1` を、環境変数から読む形に作り直す（`/backup-guide` の①手順4）

> 📌 コミット履歴から値そのものを消す方法（`git filter-repo` 等）もありますが、
> 履歴を書き換えると他の環境との同期が壊れます。
> **値を変更するほうが確実で安全です。**

## 7. 開発・保守をする人への注意

- 秘密の値を、ソースコード・設定ファイル・ドキュメント・コミットメッセージに書かないこと
- 一時ファイル（`git diff` の保存など）をリポジトリ直下に置かないこと。
  置く場合は `.gitignore` に追加し、作業後に必ず削除すること
- テストコードに本物の値を書かないこと。テスト専用の値を使うこと
- 新しい秘密の値を追加したら、**第2章の表と `SECURITY_CHECKLIST.md` 第3章に必ず行を追加する**こと
- パスワードを比較する処理を新たに書かないこと。認証はTOTPに一本化されている

### テストを実行するとき

`DB_PASSWORD` が設定されていないとテストが失敗します（DBに接続する結合テストがあるため）。

```powershell
$env:DB_PASSWORD = "（実際の値）"
.\mvnw.cmd test
```
